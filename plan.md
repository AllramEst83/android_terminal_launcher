# Terminal Launcher — Plan

Goal: an Android home-screen launcher that *is* a terminal, so the user rarely has to leave it. Plain terminal first; a richer look where information needs structure.

Guidance for agents: [AGENTS.md](AGENTS.md) and [.agents/](.agents/README.md). Each step ends with `dart format`, `flutter analyze`, `flutter test` clean and, where it touches the phone, a device check. Small steps: finish and verify one before starting the next.

The full history of Phases 0 to 9.3 (what was tried, measured and decided, with dates) is archived in [.agents/archive/plan-through-phase-9.3.md](.agents/archive/plan-through-phase-9.3.md). Durable design decisions live in [.agents/architecture.md](.agents/architecture.md).

## Not yet checked on a device

Built and tested, but not recorded as tried on the phone: `event add`/`edit`/`rm` (the write path is tested against a fake `CalendarService`, not a real calendar; the Kotlin builds and the `WRITE_CALENDAR` permission is confirmed present in a built APK, but only the phone can say the dialog appears and an event actually shows up), `timer` and `alarm` (the Kotlin builds and the Dart side is tested against a mocked channel, but only the phone's clock app can say it really started; try `timer 1m` and `alarm` for a minute ahead, and see whether your clock app honours `EXTRA_SKIP_UI` or opens itself), the history strip's look and feel, `mail` and `mail rm` (the IMAP code is tested against a local fake server, not a real provider; the hidden prompt and the Keystore only on a device; try `mail rm` on a throwaway message first), the spinner's look, `weather` from SMHI (real answers are saved as test fixtures, but the app has not run against the live API), `sms` (test with your own number first), `wa` (the Kotlin builds, but only the phone can say `wa.me` really opens WhatsApp with the number and text filled in), `call` and `contact`, the help cards, `ui plain`, the app icon, double-space, the flight-mode messages for `weather`/`texttv`/`convert`.

## Not implemented (on purpose or not yet)

- **Text TV**: the five pictures that are not block graphics (the weather sun symbol on pages 421/714, page 777's test card) stay blank; no screen-reader actions for its links.
- **App icon**: no monochrome layer for Android 13 themed icons (a silhouette of the monitor is a blob).
- **Suggestions**: no id completion for `note`/`todo` (`show`/`rm`/`done`), no currency codes for `convert`; both need a synchronous cache that is not worth the cost yet.
- **Notes**: no journal view, and no tap-to-copy on output lines (would help `calc`/`convert`).
- **Log UI**: no dimming of older blocks, collapsing of long output or timestamps on tap; only if daily use asks.
- **Errors**: a failed command is still red lines (the terminal look on purpose); only the ones that ask you to pick (several apps, people or numbers match) are cards.
- **`--plain` per command** exists on `cal`, `weather` and `help`; everywhere else `ui plain` turns the cards off.
- **View mode**: no `auto`; every command without a rich form is already plain, so it would mean the same as `rich`.
- **Calendar**: `event add`/`edit` make only timed events, no all-day ones; no recurrence, attendees, location or reminders; a repeating event's occurrences can be seen (`cal`) but not edited or removed as a series.
- **Mail**: no message body (`mail show`), search, folders or more than 20 messages; no push or background sync; no undo command (it is in Trash on the server; `mail rm` takes nothing back); no Outlook.com/Hotmail (needs OAuth).
- **Weather**: no hourly view; observed rain and present weather are not used for *now* (few stations report them), so the sky and rain now come from the forecast for the current hour; a day's low and high at the far end of the ten days rest on a few 6- or 12-hourly points; the spinner does not appear for commands that are not tagged, however long they take.
- **Timers and alarms**: set and opened only; the terminal cannot list or cancel them (the clock app owns them). Our own scheduler was left out on purpose: exact-alarm and notification permissions, a boot receiver and OEM battery rules for something the clock app already does reliably.
- **Messenger**: not added. `m.me` opens a chat by Facebook username or page id, not a phone number, so a contact's number cannot be turned into a Messenger link the way `wa.me` does for WhatsApp; would need a per-contact Messenger id stored somewhere, which is not planned.
- **History**: no editing of single entries (`history clear` forgets all), no separate history for arguments, and a `note add ...` is remembered only as `note`.
- **Later, all cheap on the current tokenizer/registry/session**: aliases, `&&` chaining, macros (which would build on history), config export, app-list refresh on install/uninstall.

- 2026-09-26: Phase 9.5: a spinner for commands tagged as slow, and SMHI instead of Open-Meteo as the preferred weather source (SMHI's old `pmp3g` API no longer exists; the new `snow1g` forecast and the `metobs` stations are used; Open-Meteo stays for places SMHI does not cover and as a fallback). Decisions in `.agents/architecture.md` ("Spinner", "Weather sources").

- 2026-09-26: Phase 9.6, command history, and 9.7, timers and alarms. The alarms item of the old Phase 10 is done the other way round than planned (the phone's clock app instead of an own scheduler, see `.agents/architecture.md`, "Timers and alarms"). Adds the `SET_ALARM` permission.

- 2026-09-27: `cal week` gets the same previous/next arrows as `cal month`, stepping a week at a time; the arrow header (`BlockNavHeader` in `block_card.dart`) is shared between the two, and `cal day` keeps its plain single heading since there's nowhere for it to step to.
- 2026-09-27: Phase 9.8, `event add`/`edit`/`rm`: calendar write access, done as a guided form, `CommandAsk` at its core. `cal day`/`cal week` now number every event they show, and share that list (`LastCalendarEvents`) with `event` so it can be named by number or by id. Messenger left out (see "Not implemented"). The help overview's row-packing width went from 32 to 34 columns to make room for the new command without pushing the overview past its 16-line budget. Decisions in `.agents/architecture.md` ("WhatsApp hand-off").
- 2026-09-27: `wa`'s text made optional (`wa <name or number> ["text"]`): one argument opens the chat empty, ready to type in WhatsApp itself, instead of always needing a quoted text. The contact card's `wa` button now fills the command ready to send as it stands (like `call`), rather than opening a quote (like `sms`, which always needs text).
